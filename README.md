# Voxelcaster

> **UE5 C++ 탑다운 로그라이크 액션 — GAS 스킬 조합, CommonUI 게임패드 UI, 데이터 드리븐 설계**

---

## 게임 소개

기본 스킬 3개에 웨이브마다 **모디파이어**(관통·분열·폭발·연쇄·가속)를 붙여 빌드가 갈리는 탑다운 로그라이크 액션입니다. "선택이 조합되어 플레이가 달라진다"를 보여 주는 것이 목표입니다.

- **한 판**: 5웨이브. 웨이브를 클리어할 때마다 카드 3장 중 1장을 골라 스킬에 모디파이어를 붙입니다
- **스킬**: 매직 볼트(투사체), 노바(지속 피해 장판), 블레이드 스윕(부채꼴 근접), 대시
- **적**: 러너(떼 지어 돌진), 슈터(거리 유지 사격), 엘리트(3방향 사격, 체력 50%에서 러너 소환)
- **조작**: 키보드·마우스, 게임패드(Xbox·PlayStation) 모두 지원
- **아트**: 서로 다른 외부 에셋(던전 팩, Paragon 캐릭터)을 카툰 포스트 프로세스로 하나의 톤으로 통일

## 직접 설계·결정한 것

- **구조**: GAS 스킬, CommonUI + MVVM, StateTree AI, 게임패드 지원, DataTable 분리와 데이터 매니저
- **게임플레이**: 모디파이어 규칙, 군집 이동, 공격 연출, 계단 이동, 벽 반투명·실루엣
- **아트·레벨**: 아트 방향, 에셋 선정, 던전 레벨, 카툰 머티리얼 노드
- **검수**: PIE로 버그를 찾아 원인 조사 지시, 구현 결과 승인·반려

## 1. GAS 스킬 + 모디파이어 조합

- 스킬 4종을 `UGameplayAbility`로 구현, 입력 태그로 발동, 쿨다운·무적은 런타임 GameplayEffect
- 명중 훅(`ApplySkillHit` → `OnSkillHit`)으로 스킬과 모디파이어를 분리
- 모디파이어 5종, 스킬당 슬롯 3칸·스택 최대 3
- 파생 명중(`bIsDerived`)으로 **모디파이어가 모디파이어를 다시 발동하는 무한 연쇄 차단**
- 성능 상한: 폭발 30명, 연쇄 프레임당 40회, 분열 투사체 동시 60개
- 트러블슈팅: 모든 쿨다운·대시 무적이 적용되지 않던 버그 → `ApplyGameplayEffectToOwner`가 **GE 클래스의 CDO**로 스펙을 만든다는 것을 추적해 `ApplyCooldown` override로 해결

## 2. CommonUI + MVVM, 게임패드 UI

- 화면: HUD, 보상 선택, 일시정지, 결과. **게임패드만으로 모든 화면 조작**
- C++ 뷰모델(FieldNotify, 값이 바뀔 때만 알림) + WBP는 View Binding만 담당
- 공용 스타일 9종(텍스트·테두리·버튼)을 C++로 정의 → 스타일만 바꾸면 전 화면 반영
- 입력 장치 자동 감지(키보드 / Xbox / PlayStation)로 키 표시·안내 문구가 즉시 전환
- 트러블슈팅
  - WBP를 만들어도 C++ 기본 화면이 뜨던 버그 → MVVM 로그 "Invalid Destination"에서 역추적, 위젯 트리 복사 전에 판단하던 초기화 순서 문제 수정
  - 재시작 후 입력이 먹지 않던 버그 → 결과 화면이 켜 둔 CommonUI 메뉴 입력 모드가 레벨을 넘어 남는 것이 원인, 레벨 시작·재시작 시 게임 입력으로 복원

## 3. 적 AI와 이동

- **StateTree**: 슈터의 접근·후퇴·사격을 상태와 조건 노드로 구성
- **군집 이동(Boids)**: 분리·정렬·결합으로 러너가 떼 지어 몰려오고, 플레이어 근처에서는 흩어져 둘러쌈
- **길찾기**: 벽에 가려지면 내비메시 경로로 우회, 웨이브는 플레이어까지 걸어서 갈 수 있고 벽과 겹치지 않는 위치에만 스폰
- 계단·경사 이동, 카메라를 가리는 벽 반투명 처리
- 타격감: 히트스톱, 게임패드 진동, 피격 플래시, 공격 시 스쿼시 앤 스트레치
- 트러블슈팅: 던전에서 캐릭터가 떠서 느리게 움직이던 문제 → 측정 치트로 `Falling` 상태와 높이 고정 확인 → 탑다운용 평면 고정 제거 → 속도 0 → 600, 계단 오르기 확인

## 4. 데이터 중심 설계

- **DataTable 7종**: 웨이브, 적(체력·속도·군집 가중치·메시·애니메이션), 스킬, 모디파이어, UI 문구(한/영), 입력 아이콘
- **데이터 매니저**(엔진 서브시스템): 테이블 경로는 프로젝트 세팅에서 지정, 게임 시작 시 **행 구조체·필수 행·값을 검사**하고 로그로 요약. 테이블이 없어도 코드 기본값으로 동작
  - 실제로 "모디파이어 테이블이 비어 있음", "문구 키 5개 누락"을 시작 로그에서 검출
- 적의 메시·애니메이션·크기까지 테이블로 교체 (애님 BP가 없는 에셋은 블렌드스페이스를 직접 재생)

## 5. 에디터 툴 (VXDataTools 플러그인)

| 도구 | 기능 |
| --- | --- |
| **데이터 리임포트** (Slate 패널 + 툴바 버튼) | 폴더의 DataTable을 원본 CSV/JSON에서 한 번에 리임포트, 원본을 못 찾으면 에셋 이름으로 자동 매칭, 결과 표시 |
| **VXBuildUI** (커맨드렛) | UI 기획서대로 **WBP 6개의 위젯 트리 + 스타일 + MVVM View Binding(40개)을 코드로 생성**하고 컴파일 검사 |
| **VXToonFixup** (커맨드렛) | 머티리얼 노드 추가·수정, 셰이더 컴파일 에러 검사, 메시 바운딩 측정, DataTable 리임포트 |
| **카툰 포스트 프로세스 적용** (메뉴) | 레벨의 Post Process Volume에 머티리얼·할레이션·색수차 값을 한 번에 설정 (Ctrl+Z 가능) |

## 6. 카툰 렌더링: 서로 다른 에셋을 하나의 톤으로

던전 팩(스타일라이즈드)과 Paragon 캐릭터(사실적 PBR)처럼 **화풍이 다른 에셋을 포스트 프로세스 하나로 통일**했습니다.

- **셀 셰이딩**: 장면 색을 BaseColor로 나눠 **빛의 양만 계단화** → 텍스처 무늬는 살리고 명암만 만화처럼
- **윤곽선**: 주변 4픽셀의 깊이(상대값)·노멀 차이로 검출, 하늘 제외
- **벽 뒤 실루엣**: Custom Depth + 스텐실로 플레이어(하늘색)·적(빨강) 구분
- **할레이션**: 블룸의 큰 번짐만 붉게, 색수차·비네트

작업 분담
- **나**: 레퍼런스를 골라 효과 조합 결정, 셀 셰이딩·윤곽선 노드 직접 구현, 톤 튜닝, 셰이딩 식의 한계 발견
- **AI**: 노드 설계·시각화, 렌더 테스트로 원인 진단, 커맨드렛으로 노드 수정

렌더 테스트로 잡은 문제
- 화면이 새까맣거나 하얗게 날아감 → 노출값을 바꿔 가며 스크린샷 비교 → Blendable Location(노출 적용 전 값) 문제로 확정, After Tonemapping으로 이동
- 밝은 곳에서 텍스처 무늬가 사라짐 → 식을 "장면 밝기"에서 "빛의 양" 기준으로 변경

## 7. AI 협업 방식 (하네스 엔지니어링)

4일이라는 기간은 AI 코딩 에이전트(Claude Code)와의 협업으로 가능했습니다. AI에게 "게임 만들어 줘"라고 맡기지 않고, **AI가 스스로 판단·검증할 수 있는 작업 환경(하네스)을 먼저 만들고** 그 안에서 일하게 했습니다.

### 7.1 문서 파이프라인: AI가 읽고 따르는 기준
```
inbox (내 아이디어, AI 수정 금지)
  → design (주제별 기획, AI 초안 → 내가 검토)
    → spec (구현 명세, 완료 조건 포함)
      → epic (일정·체크리스트)
PROGRESS.md (진행 상황·결정 사항·변경 로그)
```
- 문서끼리 **양방향 동기화**: 구현 중 기획이 바뀌면 spec → design으로 거슬러 올라가 고친다
- **결정은 사람이**: 모디파이어 스택 규칙, 보상 횟수, 아트 방향 같은 결정은 AI가 선택지를 제시하고 내가 고른다. 결정은 PROGRESS에 날짜와 함께 기록
- **코딩 규약 문서**: 접두사 `VX`, 뷰모델 `UVX_VM_`, 어빌리티 `UVX_GA_`, 조건문 `false ==` 등. AI가 모든 코드를 규약대로 작성

### 7.2 검증 루프: AI가 "됐다"고 말하기 전에 증거를 보게 함
```
코드 수정 → UBT 빌드 → 헤드리스 실행(-ExecCmds로 치트 입력)
  → 로그 grep / 오프스크린 렌더링 스크린샷 / 픽셀 차이 비교 → 보고
```
- AI가 게임 상태를 **직접 관찰할 수 있도록 계측 치트를 먼저 만들게 함**
  - `DebugMoveTest`(이동 상태·발밑 바닥·FPS 기록), `DebugEnemyFacing`(방향·경로·벽 겹침), `ToonParams`(머티리얼 파라미터 실측), `DebugScreenshot`(지연 캡처)

### 7.3 에디터를 AI의 손으로: 커맨드렛
AI는 에디터 GUI를 만질 수 없습니다. 그래서 **에디터 없이 에셋을 고치는 커맨드렛**을 만들게 해, 머티리얼 노드·WBP·DataTable까지 AI가 직접 수정하고 검증하게 했습니다 (5절).

### 7.4 작업 체계
- 문서 파이프라인, 코딩 규약, AI 메모리 규칙(사람 요청 없이 커밋 금지 등) 설계
- AI 제안 거절·오류 지적, 차기 구조(전역 이벤트 + Model/ViewModel/View) 결정

## 실행 방법

1. Unreal Engine 5.8, Visual Studio 2022를 설치합니다.
2. 아래 외부 에셋은 용량·라이선스 때문에 저장소에 없습니다. Fab에서 받아 같은 위치에 둡니다.
   - `Content/Fantastic_Dungeon_Pack/`, `Content/ParagonGRIMexe/`, `Content/ParagonMinions/`, `Content/Hero/`
3. `Voxelcaster.uproject`를 우클릭해 **Generate Visual Studio project files** → `VoxelcasterEditor` 빌드 → 에디터 실행
4. 개발용 치트(콘솔 `~`): `God`, `TestWave`, `ShowUpgradeSelect`, `GiveModifier MagicBolt Explode` 등
